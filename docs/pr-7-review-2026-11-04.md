## Findings addressed

1. **Image-stats could deadlock after earlier OpenCV work.** On Linux/Python 3.13, the process pool inherited native thread state through `fork`. The existing analysis-then-CLI test sequence stalled at the first parallel call; a bounded reproduction captured the wait. The CLI now explicitly uses `spawn`. A subprocess regression warms OpenCV, runs serial and parallel analysis with a 30-second bound, and compares the complete records. Statistics formulas and frozen outputs are unchanged.
2. **Publication validation did not reconcile all dataset representations.** Matching file hashes alone allowed a freshly generated export to carry different nested assessments or enabled image-level training masks, while the score table remained valid. Model totals also did not establish one slot per model per image. The verifier now checks exact case/model/arm coverage, equality between nested assessments and score rows, reference score agreement, and disabled image-level training masks. Six regression cases exercise these failures after updating file hashes, including consistent CSV/JSONL corruption. The existing publication passes unchanged.
3. **The full visual-quality workflow depended on an undeclared clustering environment.** Corpus modules import scikit-learn, but the documented project environment did not install it. A locked `corpus` dependency group and explicit check commands replace the prior borrowing of another experiment's environment. This maintenance environment does not supersede historical GPU environment provenance.

Ruff also found two standalone provenance scripts incorrectly treated as namespace packages and four unformatted visual-triage files. The scripts now have a scoped `INP001` exemption; the four files were formatted without changing their ASTs.
