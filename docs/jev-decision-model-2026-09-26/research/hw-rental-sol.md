# GPU rental: second opinion (2026-09-26)

**Verdict:** do not rent for first trials while local RTX 3090 (24 GB) is recoverable; fix its reported NVML driver/library mismatch first. Local hardware specification and failure are from [shared brief](../brief.md), not independently measured. [INFERENCE] Small-model LoRA/QLoRA, dataset/eval, calibration, and prompt/inference baselines should establish value before a larger GPU. Rent for *measured* VRAM shortfall, deadline pressure, or a justified 12B–27B candidate; never rent H200 just because benchmark reproductions used a 96-GB card. RunPod publishes [96-GB RTX PRO 6000 $1.69/h](https://www.runpod.io/gpu-models), [80-GB A100 PCIe $1.19/h](https://www.runpod.io/gpu-models); [Lium lists 96-GB RTX PRO 6000 Server $1.19–1.29/h with nine pods](https://lium.io/pricing). Marketplace stock and price can change before checkout.

## Provider choice and operational risk

- **RunPod = default paid baseline.** Clear GPU catalog, per-model RAM/vCPUs, modest $0.34 4090 / $0.79 L40S / $1.19 A100 / $1.69 PRO 6000 [catalog](https://www.runpod.io/gpu-models). [INFERENCE] Prefer secure/on-demand instances over cheapest community hosts for long non-resumable runs; compare actual checkout including volume/storage. Community listings are useful for short reproducible comparisons; not a documented reliability guarantee.
- **Vast = price discovery and cheap reproducible sweeps**, not blindly the minimum listing: its [live-feed methodology](https://vast.ai/pricing) distinguishes min, p10, median and available offers. [INFERENCE] Apply host reliability, bandwidth, disk and successful 10-minute smoke gates; use on-demand over interruptible unless writing checkpoints and staging them externally. Even a low $0.267 A100 floor can be a poor experiment if setup repeatedly fails; p10 is a saner planning number. Feed expressly says prices differ by host, machine reliability, network and location.
- **Lium = strong quoted 96-GB alternative** ($1.19–1.29/h PRO Server, currently nine pods), good for a *single bounded memory-bound* job if available at order time; per-second billing, browser/CLI/API [live catalog](https://lium.io/pricing). WARNING: its $0.40 5090, $0.38 L40S, $0.45 A100 PCIe are **reference prices with no rentable pods**, not purchasable bargains. Avoid depending on one market snapshot to promise availability.
- **Daytona really has GPU support**: [docs list RTX 4090/5090, PRO 6000, H100/H200, B300, MI355X](https://www.daytona.io/docs/en/sandboxes.md#gpu-sandboxes); [pricing page labels shown GPU rates “Preemptible”](https://www.daytona.io/pricing), so $0.57 4090/$0.74 5090/$1.74 PRO/$2.27 H100/$2.61 H200 must **not** be misrepresented as assured on-demand. [Docs](https://www.daytona.io/docs/en/sandboxes.md#spot-gpu-sandboxes) say spot can terminate without warning; [capacity API](https://www.daytona.io/docs/en/sandboxes.md#gpu-capacity) requires organization ID and is quota-sensitive, so **actual stock unverified**. [GPU sandboxes are ephemeral, region-flexible and can wait for capacity](https://www.daytona.io/docs/en/sandboxes.md#gpu-sandboxes). [INFERENCE] No need to rebuild our VM/SSH workflow for it; $200 advertised credits [pricing](https://www.daytona.io/pricing) may justify a short isolated trial if account terms qualify, but do not rely on it for long training.
- **TensorDock = possible VM price competitor**, but [its price table is explicitly 2024-era, host-dependent and quotes GPU only](https://www.tensordock.com/cloud-gpus.html). [It advertises 99.99% host uptime standard](https://www.tensordock.com/cloud-gpus.html), not a proven per-run SLA; check live checkout.
- **Prime Intellect = aggregation/platform premium**: its [front page](https://www.primeintellect.ai/) shows H100 $2.43, H200 $3.14, PRO 6000 $3.14 and H100 spot $0.94; spot is interruptible [INFERENCE]. Other [Prime page /compute returned HTTP 404](https://www.primeintellect.ai/compute); use working front page instead. Its integrated RL/training services add little to plain `uv` + SSH [INFERENCE].
- **Shadeform = comparison/availability backstop, not a GPU type**: [states 30+ cloud partners and no fees/markups](https://shadeform.com/prices); public page exposed no numerical selectable GPU prices in static read, so provider/GPU cost is **[UNVERIFIED] until marketplace checkout**. Useful for sourcing when desired configuration is unavailable, not an asserted lower price.
- **Modal = serverless for burst inference/eval**, not economical uninterrupted fine-tuning versus VM rates: per-second GPU+CPU+RAM and no idle GPU billing [pricing](https://modal.com/pricing); [INFERENCE] requires new function/image/dependency deployment rather than the existing SSH workflow.

## Per-useful-experiment decision rule and estimates

**First:** repair local 3090 and run one representative batch; its 24 GB and 60-GB system RAM are reported [shared brief](../brief.md). [INFERENCE] A 4090 also has 24 GB, so renting it does **not** solve an OOM; 5090 has 32 GB, only modest headroom. [INFERENCE] Measure actual batch/sequence/optimizer memory and wall-clock on local GPU, and estimate time-to-decision, not raw TFLOPS. Rent only (a) local OOM persists after legitimate QLoRA/LoRA/gradient checkpointing and useful batch settings, (b) a validated candidate needs >24 GB, or (c) measured end-to-end wall time threatens a fixed deadline and rentable throughput including setup yields >=2x completed useful experiments per calendar day. These are recommended decision thresholds, **not measured project benchmarks**.

## Workflow fit / gotchas

Existing [`scripts/sync_to_server.sh`](../../../scripts/sync_to_server.sh) rsyncs code/config/seed corpus via SSH and excludes `.venv`, `.git`, `runs`, `artifacts`, and generated data; [`scripts/server_bootstrap.sh`](../../../scripts/server_bootstrap.sh) installs uv/Python 3.13 and runs `uv sync --extra train --extra export` then `uv run … info` and prints data-build/train steps. [INFERENCE] VM/pod with SSH+rsync (RunPod, Vast, Lium, TensorDock or Prime depending actual service instance) preserves this workflow; Modal and Daytona need adaptation and cannot magically inherit local run artifacts. **Critical**: `rsync --delete` with excluded `runs/` means runs/artifacts are *not* copied back; before releasing any host explicitly pull checkpoints, metrics, logs and reproducibility metadata to local or durable object storage, and check that rented storage persists after stop. This follows directly from [`sync_to_server.sh`](../../../scripts/sync_to_server.sh). [INFERENCE] Budget ~1–2 setup hours on first instance and verify CUDA (`uv run ... model-gym info`), memory, a mini training step, and checkpoint retrieval *before* buying 24–48 hours. Do not import the local NVML mismatch into a remote instance: inspect its own driver via [`server_bootstrap.sh`](../../../scripts/server_bootstrap.sh).
