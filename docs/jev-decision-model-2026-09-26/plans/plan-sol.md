# Pragmatic experiment program: open typed decision model (2026-09-26)

All prospective runtime, quality and cost numbers below are **planning estimates and preregistered gates, not measured outcomes**. Source citations are linked research notes or primary URLs; freeze model/dataset SHA, evaluation corpus hashes, Docker image and evaluator commit before executing. No repo edits/training/evaluation were performed to prepare this program.

## 1. Thesis, and what not to do

The cheapest credible entry is a **single-forward-pass constrained-candidate model**, trained on clean diverse source-disjoint decisions, calibrated after training, with every Choice/Noul/Score option scored. Not an attempt to reproduce secret Jev architecture: Jev promises independent questions over shared state, listwise Choice, typed probabilities, Score expectation, and derived rather than learned confidence ([reference](../research/jev-reference.md), [TypeSafe API](https://docs.typesafe.ai/api)). Conventional constrained-logit readouts plus good data work: zero-training 27B Decider-chat scores **51.35** on live 0.2.1; trained 4B Decider scores **40.70**, 9B Lux **43.49**, 12B LoRA Winnow **50.02**; top Rune v3 **57.44**, AutoJev **56.40**, Jev **57.89** ([leaderboard](../research/leaderboard.md), [live results](https://huggingface.co/spaces/multimodalart/jev-decision-index/resolve/main/data/index.json)). We aim for an *honest, usable tier entry*, not pretend that 2–4B beats 27B on GPQA. A baseline and training on identical prompts are crucial: 35B Xor **41.48**, with a 26-choice cap leaving 12.09% unanswered; fine-tuning alone cannot fix incomplete interface coverage ([Xor](../research/competitor-xor.md)). Winnow's contrastive fact flips and gated teacher distributions, Rune v2's reasoning-to-one-pass soft-target distillation, AutoJev's proper CE and held-out temperature, and Decider's simple typed readout are reusable mechanisms, **not independently controlled evidence that each causes the observed gains** ([Winnow](../research/competitor-winnow.md), [Rune](../research/competitor-rune.md), [AutoJev](../research/competitor-autojev.md), [Decider](../research/competitor-decider.md)).

**Deliberate exclusions:** no 27B full FT, MoE training, original pretraining, proprietary Jev cloning as the sole objective, RL/GRPO first, fancy learned confidence head, speculative decoding, DeepSeek-style attention retrofit, or 64K-context promise without a measured requirement. The first product is text-only 2–8K; large-window support is an explicit future gate. Preserve and disclose the incumbent five-level command-risk classifier; it is a distinct **fixed-label** task, not evidence of arbitrary runtime-label ability ([README](../../../README.md), [DeepSeek papers](../research/papers-deepseek-nsa.md)).

## 2. Target and serving contract

**Primary leaderboard target:** 700M–3B served-parameter tier using `openbmb/MiniCPM5-2B` (**2.517B actual total**, not 2.0B), single BF16 LoRA r16 training on local 3090. Board reference: Decider 2B 28.97. Preregister **≥30.0 v0.2.1-equivalent index** and ≥2.0 index points over our own identical-base no-training readout before claiming a credible tier entry; if public scorer remains only 0.2, publish that edition's *separate* score, never relabel it 0.2.1. **Secondary 3B–10B tier:** Qwen3.5-4B (4.660B served) QLoRA/short-context BF16-LoRA; reference Decider 4B 40.70, target **≥41.0**, ≥2.0 gain over matched stock readout. A 350–700M encoder (ModernBERT-large ~396M or GLiClass-instruct-large ~439M) is an efficiency control, not initially the leaderboard headline; its existing fixed five-class head must be changed. K2-Horizon marketed 3.7B actually stores **5.06B** including embeddings, uses remote code with unvalidated PEFT targets: inference-only challenger if the first two bases fail, not our cheapest first train ([base inventory](../research/base-models.md), [tier scores](../research/leaderboard.md), [GLiClass](../research/papers-classification.md)).

**Product target [INFERENCE]:** one 24GiB RTX 3090 (or 16GiB quantized deployment), local `/v1/systemone`-compatible HTTP, no runtime teacher/API, batch-one 512-token Choice p50 ≤100ms / p95 ≤250ms on 3090, 2K-token p95 ≤650ms, all inclusive of tokenization + *prefill* + readout + serialization; 8K p95 measured separately, not constrained yet. These are hypotheses to validate, not board-comparable latency (board uses RTX PRO 6000, Jev hosted p50 253ms on its suite and previously 311ms on our command-risk sample). Support 1–255 Choice options, 2–10 Score levels, Noul, null/JSON instruction and description payloads, and explicit errors for unsupported overlong context; no silent label pruning or arbitrary 26-letter ceiling. State may be prefetched once and branched per question with isolated suffixes, but the correct first implementation may recompute state once per question; benchmark before engineering prefix reuse. Model sees option **descriptions**, not solely IDs; IDs/question keys never enter logits. Positive calibration temperature changes probabilities, not argmax. Choice confidence and Score confidence are deterministic TypeSafe-compatible functions; Score result is expected level, Noul P(true). This avoids confusing confidence with correctness probability ([reference](../research/jev-reference.md), [Decider serving](../research/competitor-decider.md), [Xor coverage](../research/competitor-xor.md)).

## 3. Evaluation harness **before** training

1. **Executable stack:** vendor/pin `Mapika/decider` Apache-2.0 evaluation, prompt/readout and `/v1/systemone` schema as a *reference implementation*; our own engine must expose canonical `{state,questions}` → typed answer probabilities with zero generated tokens. Run identical selected cases through Decider 2B/4B baseline and stock base using the **same own engine input/readout**; also verify reference output contract for each type. `apolinario/decision-index` pinned Git commit + corpus SHA + `decision_index` public edition **0.2** is the independently runnable published index regression suite ([kit](https://github.com/apolinario/decision-index), [harness audit](../research/leaderboard.md)). The live Space's **0.2.1 is not executable equivalently via the current public kit**: new weights, task exclusions, answerability/ACOS revisions; store its versioned `data/index-v0.2.1.json` and `methodology-v0.2.1.json`, but do **not** invent current leaderboard parity. To claim v0.2.1: get maintainer's current kit or implement published changes then independently reproduce the *published aggregate scores for multiple untouched reference entries* within rounding; retain exact scored-row manifests and normalization. Public suite rebuild needs ~7GB download/17GB space, a 2.2GB HoVer database and gated HLE access. Full suite only once after internal selection; a stratified 2K–5K local development slice can be used **only as a descriptive regression**, not for choosing checkpoints/hyperparameters ([leaderboard](../research/leaderboard.md)).
2. **Partition *before* sample inspection:** group canonical tasksource `group_id` and Open-Jev parent families; keep source-task and generated rule/template-family holdouts. Four mutually disjoint partitions: train (~70%), model-selection development (~10%), calibration (~10%, fit only temperatures after freezing weights), sealed final (~10%, task/source families never used for training/selection/calibration). Existing provider split names are not enough to guarantee source disjointness. Build an additional **new command-risk external panel** from withheld tool-family/rule templates and 200 independently reviewed gold examples; current `data/seed` shared groups cannot train and test across semantic twins. Two final sets: unseen task/source families and unseen templates within known task families; mark which is which, avoid falsely claiming both zero-shot. No public benchmark-derived inputs or labels in the final selection panel. Never pick checkpoint from board, JevBench, source-disjoint sealed panel or released competition validation; if a later model is altered after final testing, that panel is burned and a *new* sealed family is required. A single final full-board run per preregistered finalist; subsequent submissions explicitly count as exposure ([data audit](../research/datasets.md), [AutoJev selection disclosures](../research/competitor-autojev.md)).
3. **Decontamination:** pin dataset SHA/licensing. Exclude all Tasksource source datasets appearing in Decision Index (including BANKING77, CLINC, ARC, ANLI, HellaSwag, WinoGrande, HoVer, CLadder, NLI4CT and others; complete list from pinned board catalog), all known test-derived derivative corpora, and ambiguous split provenance. Cross-corpus canonical state/question/sorted-description hash; group semantic variants; 13-token shingle/MinHash near-overlap against suite rows and final holdouts; log match dispositions, not merely their count. SargeDev `openjev_v2` repeats Open-Jev v2—drop it. WANLI is MNLI-seeded: cap, and report ANLI separately. Do not promote SargeDev's own validation/test to “unseen task” if same templates occur in train. Confirm Jev-derived output use and redistribution terms before train/publish; if rights uncertain, run non-Jev arm on gold only and quarantine Jev soft corpus ([data audit](../research/datasets.md), [board exposure rules](../research/leaderboard.md)).
4. **Slice matrix:** 200 independent *base cases* per axis where feasible, reuse paired transformations but bootstrap by base-case/group, not by correlated variants: Choice/Noul/Score; K=2/4/8/16/32/64/128/255; lengths 128/512/2K/4K/8K and decisive evidence at first/middle/last; evidence scope 1/2/4/8, contiguous vs dispersed; irrelevant/hard distractors, negation/exception and fact-flip pairs, label description paraphrases, aliases and option permutations (3 seeds), incomplete/unknown evidence, structured JSON path references, text injection as data, command-risk false-safe costs. Score ordinal expected value/MAE plus full-bin proper loss; Noul binary proper loss. Analyze tasks such as Home Appliances multi-field exactness, RAGTruth/HoVer evidence, CRUXEval code, API-Bank tools, BBH—but **board test is reporting-only**, never hard-example mining ([top-mid gaps](../research/leaderboard.md), [Sparse Frontier diagnostic](../research/papers-hybrids.md), [TypeSafe jaggedness](../research/jev-reference.md)).
5. **Metrics/selection:** full task-native index, coverage and unsupported as wrong under the *pinned edition*; mean/macro by held-out family with group-bootstrap 95% CI. Probability metrics: categorical Brier = mean Σ(p−onehot)^2, hard-label NLL with ε=1e−12, 15-bin ECE per type **plus** equal-mass reliability and worst-family calibration; target soft-label KL separately (not ground-truth accuracy). AURC integrating error among accepted top-confidence fractions, risk at 80/90/95% coverage, **false-safe weighted command-risk loss** and P(severe | predicted safe). Select checkpoint on development macro NLL subject to a ≤1-point macro accuracy regression, then fit global T on calibration by NLL (per-type T only if calibration group-bootstrap NLL improves ≥0.01 with ≥500 independent labels/type); publish uncalibrated and calibrated metrics. Calibrated `confidence` is *derived from output probabilities*, not itself an accuracy probability. Latency: same hardware, fixed clock/batch, warm startup excluded but tokenization, prefill, readout, branching/serialization included; p50/p95 and throughput for 128/512/2K/8K input, K=2/16/64/255 and 1/8 sibling questions; include peak VRAM, CPU latency for encoder control. Baseline comparison paired by exact examples/format. No index gain alone excuses worse proper loss or safety ([TypeSafe confidence](../research/jev-reference.md), [board calibration/index separation](../research/leaderboard.md)).

## 4. Data / supervision

**First 40k–60k rows / 1 epoch, 512–2K actual-token median, max 4K; expand to 120k only on demonstrated source-held-out gain.** Preregister quotas, not a random giant soup: 35% Tasksource (`license_use=commercial`, capped 1k/source, remove every board-overlap source and any restrictive/unspecified row); 25% Open-Jev-v1.1 non-WANLI rule/policy/abstain families (max 1k/family, WANLI optional ≤5% of entire mixture after disclosure); 25% SargeDev `yuri_v3` Jev-labelled short scenarios **only if output rights verified**; 10% independently code-computed synthetic command/shell/JSON/path/logic minimal pairs with held-out rule families; 5% repo reviewed command-risk train groups recast as *ordinal Score* with level descriptions (note original level 1 is **most** severe, while Jev Score array is low→high—choose explicit reversed risk descriptions and remap integer indices). If Jev outputs unavailable, replace its 25% with source-clean Tasksource+Open-Jev+programmatic cases, not a fake teacher. Exclude SargeDev `openjev_v2` and questionable near-uniform yuri_v1; the latter is 32B-teacher memory relevance, not Jev. Cap repetitive templates and same-source exposure, stratify output-type target ~Choice 50% / Noul 30% / Score 20%, prefer 2–10 choices while deliberately include K=16/32/64/128/255 training examples synthesized from clean label taxonomies; avoid treating 255-label accuracy as solved by 16-option corpora ([dataset statistics](../research/datasets.md)).

**Supervision:** human/programmatic verified gold → hard CE; full finite teacher Choice/Score distribution → soft CE/KL (or BCE on Noul P(true)); for agreement-with-gold teachers mix e.g. 0.7 hard CE + 0.3 soft CE; when disagreed, retain verified hard label, flag for audit, **never force unverified teacher probabilities to be truth**. Distinguish Jev API rounded distributions from Qwen/AutoJev candidate-token distributions and from verbalized confidence. Compare hard-only vs same-row soft and fixed-budget mixed; no new teacher rental initially, since SargeDev already supplies distributions if licensable. Optional teacher: stock Qwen3.6-27B or AutoJev on a *small*, disjoint 5k hard-slice sample after 2B pilot; cross-family gold verification takes precedence over self-training. Ensure provided descriptions rather than choice keys convey semantics; randomized candidate order and answer-position mappings at training. Public source licenses and teacher-derived distribution rights tracked per row in a dataset manifest ([datasets](../research/datasets.md), [Winnow recipe](../research/competitor-winnow.md), [Rune v2](../research/competitor-rune.md)).

## 7. Risks and kill rules

- **Misleading scoreboard:** live v0.2.1 (38 counted/43 shown) differs from public kit v0.2; RouterBench/SGD excluded, gold/area weights changed. Never infer improvement from edition delta, use frozen editions separately; contamination/selection exposure bars pure unseen-task claims ([leaderboard](../research/leaderboard.md)).
- **Data rights/leakage:** SargeDev Jev responses licensed by uploader but TypeSafe/OpenRouter output-distillation rights unresolved; before training inspect terms or omit. Source-family overlap and accidental evaluation on Tasksource original benchmark train/test can fabricate generalization.
